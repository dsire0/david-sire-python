Quick Reference & Glossary

Git Time-Travel Cheat Sheet

Choosing between reset, switch --detach, revert, and reflog

1. Decision Matrix: Which Command Do You Need?

Goal Command Rewrites History? Best Used When…
Move branch pointer back & match files git reset --hard <commit> Yes (discards newer commits from branch) Commits are local/unpushed (like your 2 local commits ahead of origin/main).
Move branch pointer back, keep changes staged git reset --soft <commit> Yes You want to squash or re-commit the newer work differently.
Undo commits safely on a shared branch git revert --no-commit <commit>..HEAD No (adds a new inverse commit) Commits were already pushed and teammates pulled them.
Look around an old commit temporarily git switch --detach <commit> No You just want to run tests or inspect old code, then return via git switch -.

2. The Three Trees Affected by git reset

According to Pro Git §7.7 (Reset Demystified), Git manages three internal trees:

Flag 1. HEAD & Branch Pointer 2. Index (Staging Area) 3. Working Directory (Disk Files)
--soft Moves to target commit Unchanged (keeps newer changes staged) Unchanged
--mixed (default) Moves to target commit Reset to match target commit Unchanged (changes stay unstaged)
--hard Moves to target commit Reset to match target commit Reset to match target commit

3. Standard Safety Protocol (Copy-Paste Workflow)

Step A: Inspect Working Tree & Target Commit

git status --short --branch git log --oneline -n 5

Step B: Create a Safety Checkpoint Branch

git branch checkpoint/pre-reset HEAD

Step C: Rewind Current Branch to Target SHA

git reset --hard e792e36fb8205c56c914811e3703178ab84e63ed

Step D: Emergency Undo (If You Reset Too Far)

git reflog -n 5 git reset --hard checkpoint/pre-reset

4. Mini-Glossary

  • HEAD: The pointer to your currently checked-out branch or commit snapshot (Git Glossary).
  • Commit SHA: A 40-character hexadecimal cryptographic hash (e.g., e792e36fb8205c56c914811e3703178ab84e63ed) uniquely identifying a snapshot and its parent history.
  • Reflog (Reference Log): Local journal recording every movement of HEAD and branch tips over the last 90 days (git-reflog docs).
