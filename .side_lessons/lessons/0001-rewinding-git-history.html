2. The Knowledge: How git reset Rewinds a Branch

In Git, a branch name like main is simply a movable 40-character pointer to a commit SHA (Pro Git §3.1). When you want your branch to go back to an earlier commit and drop unpushed local commits, you use git reset:

  • git reset --hard <commit-sha> moves both HEAD and your current branch pointer (main) directly to <commit-sha>, and resets both the staging index and working directory files to match that snapshot (Pro Git §7.7).
  • Why safety checkpoints matter: Because --hard overwrites uncommitted modifications in tracked files, always run git status first and drop a lightweight backup branch (git branch checkpoint/pre-reset HEAD) before resetting.
  • Your built-in safety net (git reflog): Even after git reset --hard, Git does not immediately delete the old commits from disk. They remain recorded in your local reference log for at least 30–90 days.
